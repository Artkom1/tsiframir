# «ЦифраМир»: публичный сайт

Статический публичный сайт `https://tsiframir.ru` с Vercel Functions. Репозиторий не обслуживает `app.tsiframir.ru` и Telegram Mini App.

## Публичные маршруты

- `/` — постоянная главная бренда;
- `/forums/` — каталог форумов и встреч;
- `/forums/2026-nizhny-novgorod/` — семинар Сергея Кузнецова 1 ноября 2026 года;
- `/forums/2026-saint-petersburg/` — архив форума 13–14 июня 2026 года;
- `/tools/` — сохранённый интерфейс расчётов;
- `/privacy.html`, `/offer.html`, `/requisites.html` — юридические страницы;
- `/api/forum-interest` — серверная доставка формы интереса;
- `/api/paykeeper/checkout`, `/api/paykeeper/config`, `/api/paykeeper/callback` — защищённый контур старой событийной оплаты.

## Локальная проверка

Требуется Node.js 20 или новее.

```bash
npm ci
npm test
npm run build
npm run test:browser
```

В проекте нет отдельных команд lint и typecheck. `npm run build` собирает публичные файлы в `public-dist`, исключая служебные данные. Vercel Functions используют CommonJS. `npm test` валидирует событийную модель и серверные сценарии, Playwright проверяет публичные страницы в реальном браузере.

Семинар использует серверный HTML и `/api/seminar-quote` без кеширования. Цена и жизненный цикл рассчитываются в `api/lib/seminar-policy.js` по явным московским границам; программа и изображения задаются в `assets/data/events.json`. Текущее состояние оплаты и точные условия подключения описаны в [SEMINAR_PAYMENT.md](SEMINAR_PAYMENT.md). В данном выпуске онлайн-оплата закрыта до подключения и проверки существующей инфраструктуры; успешно оплатить или получить билет сейчас нельзя.

## Событийная модель

Единый источник — `assets/data/events.json`, схема — `assets/data/events.schema.json`. Клиентская витрина и серверная платёжная политика читают одни и те же данные.

Поддерживаются `draft`, `upcoming`, `live`, `past`, `cancelled`. Платёж допускается только для `upcoming` или `live`, при `salesOpen: true`, включённом тарифе и точном совпадении суммы. Любое неизвестное или закрытое состояние отклоняется до обращения к платёжному провайдеру.

Перед открытием продаж нового форума нужно отдельно реализовать и проверить провайдерную часть после `authorizeSale`. Пока её нет, даже корректная будущая позиция завершится безопасной ошибкой `payment_provider_not_configured_for_event`.

## Конфигурация

Секреты не хранятся в репозитории. Полный список шаблонных переменных находится в `.env.example`.

- `FORUM_INTEREST_WEBHOOK_URL` — HTTPS endpoint для доставки заявок. Если не задан, форма честно показывает ошибку и предлагает почтовый fallback.
- Аналитический ID в проекте и production-конфигурации не найден. Слой событий безопасно работает без счётчика; для реального сбора данных нужен отдельно подтверждённый загрузчик аналитики и его ID.
- PayKeeper secrets остаются только на сервере. Закрытая конфигурация старого форума больше не выдаётся клиенту.

## Выпуск

Проект уже связан с Vercel-проектом `numerology-forum-landing`. Актуальная процедура и rollback описаны в `VERCEL_SETUP.md`. Не вводите секреты в deploy-команды и не меняйте DNS или соседние домены в рамках обычного релиза сайта.
